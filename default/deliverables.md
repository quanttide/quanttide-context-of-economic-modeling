# 经济建模交付物边界

记录于 2026-08-09。除 mechanism 外，未来可纳入经济建模的交付物：

## 实体层（机制的同级实体，mechanisms.json 可扩展）

| 交付物 | 说明 | 实例 |
| --- | --- | --- |
| Game（博弈） | 机制是静态规则，博弈是动态过程 | 招聘博弈：50 人进入池子后的实际互动 |
| AgentType（参与者类型） | 类型空间（私有信息/效用函数） | 白嫖型/刷经历型/理想型（AI 三层分类） |
| Contract（契约菜单） | 多层契约设计（自选择机制） | 探索者/竞逐者 |
| Token（内部货币） | 激励工具（边际成本低、对方价值高的载体） | 培训额度换产出 |
| Signal（信号设计） | 昂贵信号空间 | 市场化微型创业（自找题） |

## 分析层（从"设计"到"验证"）

| 交付物 | 说明 | 依据 |
| --- | --- | --- |
| 均衡分析 | 分离均衡/混同均衡判定 | recruitment-mechanism.md |
| 演化模拟 | 把参与者放入规则，看如何分化流动 | design-models.md：过程导向思维 |
| 机制比较 | 不同规则集下的结果对比 | ROADMAP 后续目标 |

## 生态层（跨领域机制）

- 跨领域机制：招聘→课程导流、定价博弈、平台转化
- 平台设计：双边市场/平台生态博弈（platform-investment.md 方向）

## 知识层（沉淀物）

- 模型库：机制/博弈规格化沉淀
- 案例库：招聘博弈是第一个案例，未来每个真实博弈一个案例
- 分析报告：深度博弈论分析（如 mechanism/recuirtment-mechanism.md）

## CLI 映射（交付物 = 命令/子命令）

```
clarify   → 需求澄清（已有）
design    → 规格设计（已有，--type mechanism/game/contract）
simulate  → 演化模拟（未来：把参与者放入规则看分化）
analyze   → 均衡分析（未来：分离/混同判定）
library   → 模型库/案例库（未来：沉淀与检索）
```

一句话：机制是**设计物**（规则），经济建模的交付物从"设计物"向"验证物"（分析/模拟）和"生态物"（跨领域机制）延伸，最终沉淀为**知识资产**（模型库/案例库）。
